# Movies Explorer

## Описание проекта

«Movies Explorer» — это интерактивный сайт с авторизацией и регистрацией, реализованный в рамках дипломного проекта курса веб-разработки.

Пользователь может:

- зарегистрироваться и авторизоваться;
- искать фильмы по названию на русском и английском языках;
- переключаться между полным списком фильмов и короткометражками (до 40 минут);
- сохранять фильмы в личную коллекцию и удалять их;
- просматривать сохранённые фильмы и фильтровать их по названию и длительности;
- изменять имя и email в профиле;
- выходить из аккаунта.

## Функциональность и детали реализации

- **Роутинг.** Используется `BrowserRouter` и `Routes`. Маршруты `/movies`, `/saved-movies`, `/profile` доступны только авторизованному пользователю — их рендерит `ProtectedRoute`, который перенаправляет неавторизованного посетителя на `/signin`. Все неизвестные пути обрабатываются маршрутом `*` с переходом на страницу `/404`.
- **Авторизация.** Запросы `register`, `authorize`, `getContent` описаны в `src/utils/duckAuth.js`. Токен хранится в cookie (используется `credentials: 'include'`), при загрузке приложения выполняется проверка токена запросом `GET /users/me`. Пока проверка не завершена, показывается прелоадер.
- **Работа с API.** HTTP-запросы инкапсулированы в классы `Api`:
  - `src/utils/ApiMain.js` — пользовательские данные (`GET`/`PATCH /users/me`), коллекция фильмов (`GET`/`POST`/`DELETE /movies`), выход (`POST /signout`);
  - `src/utils/MoviesApi.js` — получение списка фильмов из открытого источника данных.
- **Состояние.** Пользовательские данные и статус авторизации хранятся в Redux; остальное состояние (списки фильмов, результаты поиска, флаги «только короткометражки», тексты ошибок) — в `useState` компонента `App` и передаётся вниз через пропсы. Данные текущего пользователя дополнительно прокидываются через `CurrentUserContext`.
- **Поиск и фильтрация.** Поиск выполняется по `nameRU` и `nameEN` без учёта регистра. Состояние поиска и переключателя «только короткометражки» сохраняется в `localStorage` и восстанавливается при следующем визите.
- **Адаптивность.** Количество карточек в строке и число первоначально отображаемых карточек заданы константами в `src/utils/constants.js`; брейкпоинты определяются через кастомный хук `useMediaQuery` (`src/hooks/useMediaQuery.js`).
- **Валидация форм.** Используются `react-hook-form` и `yup` (проверка email, обязательность имени и пароля, минимальная длина пароля).
- **Обработка ошибок.** Состояние сервера отображается на странице `/404`, ошибки запросов (401, 409, 429) показываются пользователю в текстовом виде под полями форм.

## Запуск проекта

Требуется Node.js 14+ и npm.

```bash
# установка зависимостей
npm install

# запуск dev-сервера
npm start
```

Приложение будет доступно по адресу [http://localhost:3000](http://localhost:3000).

### Бэкенд

Базовый URL бэкенда указан в двух местах:

- `src/utils/ApiMain.js` — поле `url` создаваемого экземпляра `api`;
- `src/utils/duckAuth.js` — константа `BASE_URL`.

По умолчанию используется локальный адрес `http://localhost:3003/api`. Для работы с развёрнутым бэкендом замените значение на `https://movies.mao321.keenetic.pro/api`.

### Продакшен-сборка и тесты

```bash
npm run build   # сборка оптимизированной версии в папке build
npm test        # запуск тестов (CRA / Jest + React Testing Library)
```

Собранная версия — в директории `build`.

## Планируемые доработки

- вынести состояние фильмов и коллекции из `App` в Redux-редьюсеры;
- управлять базовым URL через переменные окружения (`.env`) вместо хардкода;
- покрыть тестами формы авторизации, регистрации и компонент карточки фильма;
- добавить состояние загрузки изображений и плавную анимацию появления карточек.
